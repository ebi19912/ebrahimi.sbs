# جزوه جامع آموزش Microsoft Azure برای تحلیلگران داده (بوت‌کمپ ۲۰۲۶)

رایانش ابری (Cloud Computing) دیگر یک مهارت «امتیازآور» در رزومه نیست، بلکه یک «الزام» در دنیای مهندسی و تحلیل داده است. با حجم عظیم داده‌هایی که روزانه تولید می‌شوند، سرورهای محلی (On-Premise) و سیستم‌های شخصی دیگر توانایی پردازش آن‌ها را ندارند. شرکت مایکروسافت با پلتفرم **Microsoft Azure**، یکی از قدرتمندترین و یکپارچه‌ترین اکوسیستم‌ها را برای ذخیره‌سازی، دگرگون‌سازی و تحلیل داده‌ها فراهم کرده است.

این جزوه، مفاهیم و سرویس‌های کلیدی Azure را که هر تحلیل‌گر داده باید بداند، بررسی می‌کند.

---

## ۱. چرا Azure؟ (موقعیت ابری مایکروسافت)

اکوسیستم مایکروسافت یکپارچگی بی‌نظیری دارد. اگر یک سازمان از ویندوز، اکسل، SQL Server و Power BI استفاده کند، منطقی‌ترین و سازگارترین انتخاب ابری برای آن‌ها **Azure** خواهد بود.

### تفاوت سرور محلی (On-Prem) با سرویس ابری (Cloud)
* **On-Premises:** خرید فیزیکی سرور، استخدام مسئول شبکه، هزینه ثابت، محدودیت در ارتقای سخت‌افزار.
* **Cloud (Azure):** اجاره سرور و فضای ذخیره‌سازی از دیتاسنترهای مایکروسافت، پرداخت به ازای مصرف (Pay-as-you-go)، مقیاس‌پذیری بی‌نهایت (افزایش رم و هارد با یک کلیک).

---

## ۲. سرویس‌های حیاتی Azure برای تحلیل‌گران داده

در پنل کاربری Azure صدها سرویس وجود دارد، اما یک تحلیل‌گر و مهندس داده عمدتاً با ۴ سرویس اصلی زیر سروکار دارد:

### الف) ذخیره‌سازی داده (Storage)

1. **Azure Blob Storage:**
   * **مفهوم:** معادل یک هارد درایو بی‌نهایت روی اینترنت. Blob مخفف Binary Large Object است.
   * **کاربرد:** ذخیره هر نوع فایل بدون ساختار (Unstructured Data) مانند تصاویر، ویدیوها، فایل‌های متنی و لاگ‌ها.
   * **ساختار:** Account > Container > Blob (فایل).

2. **Azure Data Lake Storage (ADLS Gen2):**
   * **مفهوم:** نسل پیشرفته Blob Storage که برای تحلیل کلان‌داده (Big Data) بهینه‌سازی شده است.
   * **تفاوت با Blob:** دارای ساختار سلسله‌مراتبی (Hierarchical Namespace) است؛ یعنی می‌توانید فایل‌ها را دقیقاً مثل ویندوز داخل پوشه‌ها (Folders) قرار دهید که سرعت جستجو و خواندن داده‌ها را به شدت افزایش می‌دهد.
   * **کاربرد:** منبع اصلی ذخیره داده‌های خام (Raw Data) پیش از پردازش.

### ب) انتقال و یکپارچه‌سازی داده (Data Integration)

3. **Azure Data Factory (ADF):**
   * **مفهوم:** سرویس ارکستراسیون (Orchestration) و ETL (استخراج، تبدیل، بارگذاری) در محیط ابری.
   * **کاربرد:** ساخت پایپ‌لاین‌های اتوماتیک. مثلاً: «هر روز ساعت ۱۲ شب، فایل‌های CSV را از یک سرور خارجی بگیر، کپی کن داخل Data Lake، اگر موفقیت‌آمیز بود به دیتابیس بفرست و به مدیر ایمیل بزن».
   * **ویژگی:** محیط بصری (Drag & Drop) قدرتمند بدون نیاز به کدنویسی سنگین، با قابلیت اتصال به بیش از ۱۰۰ منبع داده مختلف (SQL, Oracle, Salesforce و غیره).

### ج) پردازش و انبار داده (Data Warehousing)

4. **Azure Synapse Analytics:**
   * **مفهوم:** تکامل‌یافتهِ Azure SQL Data Warehouse. یک محیط یکپارچه (Workspace) که هم دیتابیس‌های رابطه‌ای بزرگ و هم موتورهای پردازش کلان‌داده (Apache Spark) را در خود جای داده است.
   * **کاربرد:** اجرای کوئری‌های SQL فوق‌سنگین روی پتابایت‌ها داده. در سیناپس می‌توانید مستقیماً فایل‌های ذخیره‌شده در Data Lake را با دستورات SQL کوئری بگیرید بدون اینکه آن‌ها را وارد دیتابیس کنید (ویژگی Serverless SQL).

## ۳. معماری مدرن داده در Azure (پروژه عملیاتی)

یک تحلیل‌گر داده باید جریان حرکت داده (Data Flow) را در محیط ابری درک کند. معماری استاندارد **Medallion Architecture** (برنز، نقره، طلا) نام دارد.

### سناریوی عملیاتی یک شرکت خرده‌فروشی:

```text
[منابع خارجی: CRM, سایت, فایل‌ها]
       │
       ▼  (Azure Data Factory برای استخراج روزانه)
       │
[لایه برنز / Raw] - در Azure Data Lake
       │  (داده‌های خام و دست‌نخورده، دقیقاً با فرمت اصلی)
       │
       ▼  (پردازش با Azure Databricks یا Synapse)
       │
[لایه نقره / Cleansed] - در Azure Data Lake
       │  (داده‌های پاک‌سازی شده، حذف مقادیر نال، فیلتر شده)
       │
       ▼  (محاسبات تجمیعی نهایی با SQL)
       │
[لایه طلا / Curated] - در Azure Synapse Analytics
       │  (جداول نهایی، آماده برای ارائه به مدیران)
       │
       ▼
[داشبورد مدیریتی] - در Power BI
```

## ۴. اتصال Power BI به Azure

یکی از جذابیت‌های بزرگ اکوسیستم مایکروسافت این است که Power BI به صورت بومی (Native) با Azure متصل می‌شود:

1. وارد Power BI Desktop شوید.
2. روی **Get Data** کلیک کنید.
3. در تب Azure، می‌توانید به سرویس‌های مختلف وصل شوید:
   * **Azure SQL Database:** برای خواندن جداول سنتی.
   * **Azure Synapse Analytics:** برای کوئری‌های کلان‌داده.
   * **Azure Blob Storage / Data Lake:** برای خواندن مستقیم فایل‌های CSV/Parquet از فضای ابری.
4. با وارد کردن Credentials (مشخصات سرور و پسورد)، داده‌ها با سرعت بالا وارد مدل تبولار Power BI می‌شوند.

## ۵. سوالات پرتکرار مصاحبه‌های استخدامی Azure

1. **تفاوت بین Data Lake و Data Warehouse چیست؟**
   * *پاسخ:* Data Lake (دریاچه داده) برای ذخیره ارزانِ حجم عظیمی از داده‌های بدون ساختار (Unstructured) و خام مثل ویدیوها، لاگ‌ها و فایل‌های جیسون استفاده می‌شود. اما Data Warehouse (انبار داده) برای ذخیره داده‌های بهینه‌شده، ساختاریافته (Structured) و رابطه‌ای برای گزارش‌گیری سریع استفاده می‌شود.

2. **در Azure Data Factory، تفاوت بین Pipeline و Activity چیست؟**
   * *پاسخ:* پایپ‌لاین (Pipeline) ظرفی است که شامل مجموعه‌ای از وظایف منطقی است (مثلاً کل فرآیند کپی و تبدیل). اکتیویتی (Activity) تک‌تکِ آن وظایف اجرایی داخل پایپ‌لاین است (مانند Copy Data Activity یا Execute SQL Activity).

3. **چرا از ADLS Gen2 به جای Blob Storage استاندارد برای بیگ‌دیتا استفاده می‌کنیم؟**
   * *پاسخ:* به دلیل ویژگی Hierarchical Namespace در Gen2. در Blob استاندارد پوشه واقعی وجود ندارد (فقط نام‌گذاری مجازی است)، اما Gen2 ساختار فولدربندی واقعی دارد که باعث می‌شود عملیات‌هایی مثل خواندن یا تغییر نام دایرکتوری‌ها در سطح Big Data بسیار سریع‌تر انجام شود.

## ۶. چک‌لیست رزومه و گواهینامه‌های ابری

برای اثبات مهارت‌های خود در Azure، اخذ گواهینامه‌های رسمی مایکروسافت به شدت پیشنهاد می‌شود:

* **AZ-900 (Azure Fundamentals):** اثبات آشنایی با مفاهیم پایه ابر (مناسب برای مبتدیان).
* **DP-900 (Azure Data Fundamentals):** آشنایی با مفاهیم داده‌های رابطه‌ای و غیررابطه‌ای در آژور (ایده‌آل برای تحلیل‌گران).
* **DP-203 (Data Engineering on Microsoft Azure):** گواهینامه حرفه‌ای و سنگین برای مهندسان داده.

در رزومه خود، حتماً از کلمات کلیدی نظیر `Azure Data Lake`, `Azure Data Factory (ADF)`, و `ETL Pipelines` برای عبور از فیلتر سیستم‌های ATS استفاده کنید.
