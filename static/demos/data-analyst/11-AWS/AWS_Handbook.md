# جزوه جامع آموزش Amazon Web Services (AWS) برای تحلیلگران داده (بوت‌کمپ ۲۰۲۶)

پلتفرم **AWS (Amazon Web Services)** بزرگترین، بالغ‌ترین و پرکاربردترین ارائه‌دهنده خدمات ابری در جهان است. در حالی که Azure در شرکت‌های استفاده‌کننده از محصولات مایکروسافت محبوب است، AWS بیشترین سهم بازار جهانی (Market Share) را در میان استارتاپ‌ها، شرکت‌های تکنولوژی‌محور و غول‌های فناوری در اختیار دارد.

این جزوه، سرویس‌های حیاتی AWS را که هر تحلیل‌گر داده و مهندس داده برای ورود به بازار کار باید بشناسد، تشریح می‌کند.

---

## ۱. جایگاه AWS در دنیای داده

چرا یادگیری AWS اهمیت دارد؟
* **سهم بازار غالب:** یادگیری AWS شما را برای طیف وسیع‌تری از فرصت‌های شغلی (به خصوص در استارتاپ‌ها و شرکت‌های مدرن) آماده می‌کند.
* **تنوع سرویس‌ها:** آمازون برای هر نیاز داده‌ای، یک سرویس تخصصی و بهینه‌شده توسعه داده است.
* **متن‌باز دوستانه:** AWS سازگاری بسیار بالایی با ابزارهای متن‌باز (Open-Source) مانند Apache Spark، Hadoop و Python دارد.

---

## ۲. سرویس‌های حیاتی AWS برای تحلیل‌گران داده

در اکوسیستم آمازون، ده‌ها سرویس دیتایی وجود دارد. اما این ۴ سرویس، ستون فقرات رزومه یک تحلیل‌گر و مهندس داده محسوب می‌شوند:

### الف) ذخیره‌سازی داده (Storage)

1. **Amazon S3 (Simple Storage Service):**
   * **مفهوم:** قلب تپنده اکوسیستم داده در AWS. یک فضای ذخیره‌سازی ابری بی‌نهایت برای ذخیره هر نوع فایل (تصویر، ویدیو، CSV، JSON).
   * **کاربرد:** S3 در واقع همان **Data Lake** آمازون است. تمامی داده‌های خام پیش از هرگونه پردازشی ابتدا در S3 فرود می‌آیند (Landing Zone).
   * **ساختار:** در S3 داده‌ها داخل سطل‌هایی به نام `Bucket` ریخته می‌شوند.

### ب) انبار داده (Data Warehousing)

2. **Amazon Redshift:**
   * **مفهوم:** انبار داده (Data Warehouse) فوق‌سریع و مقیاس‌پذیرِ آمازون که برای پردازش‌های سنگین تحلیلی (OLAP) طراحی شده است.
   * **کاربرد:** زمانی که صدها گیگابایت یا ترابایت داده تمیز دارید و می‌خواهید داشبوردها (مثل Tableau) را به آن وصل کنید، دیتابیس‌های معمولی قفل می‌کنند؛ اما Redshift با معماری ذخیره‌سازی ستونی (Columnar) کوئری‌های تحلیلی را در کسری از ثانیه اجرا می‌کند.
   * **معادل Azure:** معادل Azure Synapse Analytics است.

### ج) جستجو و کوئری‌گیری درجا (Serverless Querying)

3. **Amazon Athena:**
   * **مفهوم:** یکی از جذاب‌ترین ابزارهای تحلیلگران داده. یک سرویس Serverless (بدون نیاز به راه‌اندازی سرور) که به شما اجازه می‌دهد **مستقیماً** روی فایل‌های متنی داخل S3 کوئری SQL بزنید!
   * **کاربرد:** فرض کنید یک فایل `logs.csv` پنجاه گیگابایتی داخل S3 دارید. به جای اینکه آن را وارد دیتابیس کنید، با Athena مستقیماً روی فایل `SELECT` می‌زنید و آمازون فقط به ازای دیتای خوانده‌شده از شما پول می‌گیرد.

### د) پردازش و ETL کلان‌داده

4. **AWS Glue:**
   * **مفهوم:** سرویس کامل ETL (Extract, Transform, Load) آمازون.
   * **کاربرد:** فایل‌های خام را از S3 می‌گیرد، با استفاده از پایتون یا اسپارک (Spark) کثیفی‌ها را پاک می‌کند، ستون‌ها را تغییر می‌دهد و فایل نهایی را برای Redshift آماده می‌کند.
   * **ویژگی متمایز:** Glue قابلیتی به نام *Crawler* دارد که در S3 می‌خزد و به صورت خودکار می‌فهمد فایل‌ها چه ستون‌ها و تایپ‌هایی دارند (ساخت Data Catalog).

## ۳. معماری مدرن داده در AWS (سناریوی عملیاتی)

مسیر حرکت داده از لحظه تولید تا رسیدن به دست مدیران در پلتفرم آمازون به این شکل است:

```text
[منابع خارجی: وب‌سایت, لاگ‌ها, دیتابیس‌های ابری]
       │
       ▼  (ورود داده‌های خام)
       │
[Amazon S3 - Raw Bucket]  <-- این Data Lake ماست
       │  (داده‌های دست‌نخورده با فرمت JSON یا CSV)
       │
       ▼  (ارکستراسیون و پردازش خودکار)
       │
[AWS Glue (ETL)]
       │  (پاک‌سازی مقادیر نال، تغییر فرمت به Parquet برای سرعت بیشتر)
       │
       ▼
[Amazon S3 - Cleansed Bucket]
       │  (داده‌های تمیز شده)
       │
       ├─────────────────────────────────┐
       ▼                                 ▼
[Amazon Redshift]                 [Amazon Athena]
(انبار داده برای کوئری‌های سنگین)   (برای کوئری سریع و موقت مستقیم روی S3)
       │                                 │
       ▼                                 ▼
[داشبوردهای Tableau / QuickSight]
```

## ۴. تفاوت فرمت‌های ذخیره‌سازی ابری (CSV در برابر Parquet)

یکی از مفاهیم بسیار مهم در مصاحبه‌های AWS، درک فرمت **Parquet** است.

* **CSV:** ساختار سطری (Row-based) دارد. اگر یک فایل CSV حاوی ۱۰۰ ستون داشته باشید و فقط بخواهید مجموع یک ستون (مثلاً درآمد) را حساب کنید، موتور پردازشی مجبور است کل ۱۰۰ ستون را خط به خط از روی هارد بخواند (بسیار کند و پرهزینه در ابر).
* **Parquet:** ساختار ستونی (Columnar) دارد. داده‌های هر ستون در کنار هم ذخیره می‌شوند. اگر فقط ستون 'درآمد' را بخوانید، فقط همان بخش کوچکی از فایل لود می‌شود. این کار سرعت Athena و Redshift را تا ۱۰۰ برابر افزایش داده و هزینه‌های ابری را به شدت کاهش می‌دهد.

## ۵. سوالات پرتکرار مصاحبه‌های استخدامی AWS

1. **تفاوت Amazon S3 و Amazon EBS چیست؟**
   * *پاسخ:* S3 یک فضای ذخیره‌سازی شیءگرا (Object Storage) برای نگهداری فایل‌ها و ساخت Data Lake است. اما EBS یک هارد درایو (Block Storage) است که مستقیماً به ماشین‌های مجازی (EC2) متصل می‌شود تا سیستم‌عامل روی آن نصب شود.

2. **چرا قبل از استفاده از Athena، فایل‌های CSV را به Parquet تبدیل می‌کنیم؟**
   * *پاسخ:* چون Athena هزینه‌اش را بر اساس حجم دیتای اسکن‌شده (به ازای هر ترابایت) محاسبه می‌کند. Parquet داده‌ها را فشرده می‌کند و ساختار ستونی دارد؛ در نتیجه وقتی کوئری می‌زنیم، Athena فقط ستون‌های مورد نیاز را می‌خواند که هم سرعت بسیار بالاتری دارد و هم هزینه را تا ۹۰ درصد کاهش می‌دهد.

3. **آیا می‌توان از Amazon Redshift به عنوان دیتابیس اپلیکیشن (OLTP) استفاده کرد؟**
   * *پاسخ:* خیر. Redshift یک انبار داده برای پردازش‌های تحلیلی (OLAP) است و برای `SELECT` های سنگین روی میلیون‌ها رکورد ساخته شده است. برای دیتابیس اپلیکیشن که پر از تراکنش‌های کوچک `INSERT` و `UPDATE` است، باید از Amazon RDS یا DynamoDB استفاده کرد.

## ۶. چک‌لیست رزومه و گواهینامه‌های ابری

برای اثبات مهارت در AWS، اخذ گواهینامه‌های رسمی به شدت مسیر استخدام را هموار می‌کند:

* **AWS Certified Cloud Practitioner:** اثبات آشنایی پایه‌ای با سرویس‌های کلود آمازون (مناسب مبتدیان).
* **AWS Certified Data Engineer - Associate:** گواهینامه تخصصی برای مهندسان و تحلیلگران کلان‌داده.
* **AWS Certified Machine Learning - Specialty:** برای کسانی که قصد دارند مدل‌های هوش مصنوعی را روی داده‌های AWS پیاده‌سازی کنند.

> **نکته رزومه‌نویسی:** به جای نوشتن جمله کلی «آشنایی با AWS»، بنویسید: «طراحی پایپ‌لاین ETL با **AWS Glue** جهت تبدیل فایل‌های CSV به Parquet و ذخیره‌سازی در **Amazon S3** برای بهینه‌سازی کوئری‌های **Athena**.»
