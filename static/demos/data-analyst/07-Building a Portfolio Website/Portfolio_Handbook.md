# جزوه جامع و راهنمای گام‌به‌گام ساخت وب‌سایت پورتفولیو تحلیل داده (بوت‌کمپ ۲۰۲۶)

داشتن یک وب‌سایت پورتفولیو اختصاصی، یکی از مؤثرترین روش‌ها برای اثبات عملی مهارت‌ها و متمایز شدن در بازار کار تحلیل داده است. این جزوه بر اساس سرفصل‌ها و استانداردهای ارائه‌شده در بوت‌کمپ جامع تحلیل داده ۲۰۲۶ تنظیم شده است و فرایند صفر تا صد راه‌اندازی، شخصی‌سازی و انتشار یک پورتفولیوی حرفه‌ای با استفاده از ابزارهای رایگان و قالب‌های استاندارد را تشریح می‌کند.

---

## ۱. چرایی و فلسفه ساخت وب‌سایت پورتفولیو

وب‌سایت پورتفولیو پایگاهی متمرکز برای ذخیره، مستندسازی و نمایش پروژه‌های داده‌محور به کارفرمایان و مدیران استخدام است.

### دو مزیت حیاتی داشتن پورتفولیو در فرایند استخدام:

1. **افزایش شانس دریافت دعوت‌نامه مصاحبه (Landing the Interview):** هنگامی که لینک پورتفولیو در رزومه قرار می‌گیرد، مدیران استخدام با کلیک روی آن مستقیماً خروجی کار، تسلط فنی و کیفیت پروژه‌ها را مشاهده می‌کنند.


2. **پاسخ‌گویی مستند و معتبر در مصاحبه‌های فنی و رفتاری:** زمانی که در مصاحبه درباره نحوه کار با ابزارهایی مانند SQL، اکسل، Tableau یا پایتون سوال می‌شود، به جای پاسخ‌های کلی مانند «در دوره‌های آموزشی آن را یاد گرفته‌ام»، می‌توان به پروژه‌ای عینی ارجاع داد (مثلاً: «داده‌ها در اکسل پاک‌سازی شد، سپس در Tableau داشبورد تعاملی پیاده شد و این بینش‌های تجاری به دست آمد»).



> **توصیه استاندارد بوت‌کمپ:** ساخت ۳ الی ۵ پروژه عمیق و کاربردی پیش از شروع ارسال رزومه‌ها پیشنهاد می‌شود؛ اجرای هر پروژه باکیفیت معمولاً بین ۱ الی ۲ هفته زمان می‌برد.
> 
>

## ۲. روش‌های فنی پیاده‌سازی پورتفولیو

برای راه‌اندازی وب‌سایت پورتفولیو تحلیل داده، دو رویکرد اصلی وجود دارد:

| روش | ابزارها | مزایا | معایب |
| --- | --- | --- | --- |
| **سایت‌سازهای بدون کد (Website Builders)** | Wix.com و موارد مشابه

 | عدم نیاز به ویرایش کد، راه‌اندازی دیداری سریع

 | محدودیت در شخصی‌سازی عمیق، وجود تبلیغات در پلن رایگان |
| **میزبانی مستقل ابری (GitHub Pages)** | HTML5 Templates + GitHub Pages

 | **۱۰۰٪ رایگان**، نمایش تسلط به Git/GitHub، دامنه اختصاصی `github.io`<br> | نیاز به ویرایش کدهای HTML و CSS پایه

 |

### سبک‌های نمایش محتوا در وب‌سایت:

* **مدل ویترین پروژه (Project Showcase):** تمرکز اصلی روی تصاویر داشبوردها، کارت‌های مرتب و لینک مستقیم به مخازن کد (GitHub) یا داشبوردهای آنلاین (Tableau Public).


* **مدل وبلاگی / مطالعه موردی (Narrative / Case Study):** توضیح روایی سناریوی تجاری، درج اسکرین‌شات‌های مرحله‌به‌مرحله و قطعه‌کدهای حل مسئله که منطق تحلیلی تحلیل‌گر را شرح می‌دهد.

## ۳. پیاده‌سازی عملی با قالب HTML5 و میزبانی رایگان GitHub Pages

در این رویکرد، از قالب‌های آماده و واکنش‌گرای وب‌سایت (مانند قالب معروف **Massively** ارائه‌شده در پلتفرم HTML5 UP) استفاده می‌شود.

### ساختار فایل‌های پروژه:

```text
my-portfolio/
│
├── index.html        # فایل اصلی کدهای ساختار صفحه
├── assets/           # استایل‌ها (CSS)، اسکریپت‌ها (JS) و فونت‌ها
└── images/           # تصاویر بندانگشتی و اسکرین‌شات‌های پروژه‌ها

```

## ۴. شخصی‌سازی فایل `index.html` (بخش به بخش)

برای ویرایش فایل `index.html` می‌توان از ادیتورهایی مانند VS Code یا Notepad++ استفاده کرد.

### بخش اول: عنوان مرورگر و متادیتا

در بخش `<head>`، تگ `<title>` هویت تب مرورگر را تعیین می‌کند:

```html
<title>پورتفولیو تحلیل داده | نام و نام‌خانوادگی</title>

```

### بخش دوم: سربرگ (Header) و معرفی اولیه (Bio)

در بخش ابتدایی صفحه، معرفی مختصر، مهارت‌های کلیدی و لینک‌های شبکه‌های اجتماعی قرار می‌گیرد:

```html
<header id="header">
    <a href="index.html" class="logo">تحلیل‌گر داده</a>
</header>

<div id="intro">
    <h1>پورتفولیو تحلیل داده<br />نام شما</h1>
    <p>تحلیل‌گر داده مسلط به SQL، اکسل، Tableau، پایتون و مدل‌سازی آماری[cite: 1].</p>
    <ul class="actions">
        <li><a href="#header" class="button icon solid solo fa-arrow-down scrolly">مشاهده پروژه‌ها</a></li>
    </ul>
</div>

```

### بخش سوم: لینک‌دهی به شبکه‌های حرفه‌ای (Nav / Social Links)

آیکون‌های شبکه اجتماعی به پروفایل لینکدین، مخزن گیت‌هاب یا کانال آموزشی متصل می‌شوند:

```html
<ul class="icons">
    <li><a href="https://linkedin.com/in/yourprofile" class="icon brands fa-linkedin"><span class="label">LinkedIn</span></a></li>
    <li><a href="https://github.com/yourusername" class="icon brands fa-github"><span class="label">GitHub</span></a></li>
</ul>

```

## ۵. معماری بخش پروژه‌ها در پورتفولیو

پروژه‌ها به دو دسته تقسیم می‌شوند: یک «پروژه ویژه و شاخص» در بالا و سایر «پروژه‌های استاندارد» در بخش گرید شبکه.

### الف) پروژه شاخص (Featured Post)

این بخش جایگاه چشم‌گیرترین پروژه شماست (مانند پروژه پاک‌سازی داده با SQL):

```html
<article class="post featured">
    <header class="major">
        <h2><a href="https://github.com/username/data-cleaning-sql">پاک‌سازی داده مسکن با SQL Server[cite: 1]</a></h2>
        <p>در این پروژه، داده‌های خام و ساختارنیافته حوزه مسکن با استفاده از دستورات پیشرفته SQL Server، عبارات شرطی و نرمال‌سازی تبدیل به داده‌های استاندارد و آماده تحلیل گردید[cite: 1].</p>
    </header>
    <a href="https://github.com/username/data-cleaning-sql" class="image main"><img src="images/housing.jpeg" alt="پروژه پاک‌سازی داده مسکن" /></a>
    <ul class="actions special">
        <li><a href="https://github.com/username/data-cleaning-sql" class="button large">مشاهده پروژه (View Project)[cite: 1]</a></li>
    </ul>
</article>

```

> **نکته کلیدی لینک‌دهی:** همواره آدرس مخزن یا داشبورد (`href`) را در سه نقطه قرار دهید تا کاربر با کلیک روی **عنوان پروژه**، **تصویر کاور** یا **دکمه View Project** مستقیماً به صفحه پروژه هدایت شود. متن دکمه‌ها را به جای عبارات عمومی مانند «Full Story» به «View Project» تغییر دهید.
> 
>

## ۶. به‌روزرسانی دارایی‌های بصری (پوشه Images)

تصاویر پیش‌فرض قالب باید با اسکرین‌شات‌های واقعی از پروژه‌ها جایگزین شوند:

1. ذخیره اسکرین‌شات واضح از داشبورد تبلو، نمودارهای مصورسازی پایتون یا دیاگرام مدل داده.


2. قرار دادن فایل‌های تصویری در پوشه `images/` پروژه.


3. هم‌نام‌سازی فایل‌ها در تگ `<img>` در کدهای HTML (مانند `images/housing.jpeg`، `images/covid.jpg` و `images/tableau.jpg`).

## ۷. مراحل انتشار رایگان وب‌سایت روی GitHub Pages

پس از شخصی‌سازی فایل‌های محلی، وب‌سایت روی هاست گیت‌هاب بارگذاری و فعال می‌شود:

### گام اول: ساخت ریپازیتوری در گیت‌هاب

* وارد اکانت GitHub شده و یک مخزن عمومی (Public Repository) جدید با فرمت زیر بسازید:
```text
<username>.github.io

```


*(اگر نام کاربری شما `alexdata` باشد، نام مخزن باید `alexdata.github.io` باشد).*

### گام دوم: آپلود فایل‌ها به مخزن

فایل‌های پروژه را با استفاده از ترمینال Git یا مستقیماً از طریق پنل وب گیت‌هاب آپلود کنید:

```bash
git init
git add .
git commit -m "Initial commit of portfolio website"
git branch -M main
git remote add origin https://github.com/<username>/<username>.github.io.git
git push -u origin main

```

### گام سوم: فعال‌سازی در تنظیمات (Settings)

1. به تب **Settings** ریپازیتوری بروید.
2. از منوی سمت چپ بخش **Pages** را انتخاب کنید.
3. در قسمت **Build and deployment**، منبع (Source) را روی شاخه **Deploy from a branch** و شاخه را روی **main / root** قرار دهید.
4. پس از چند دقیقه، وب‌سایت روی آدرس `https://<username>.github.io` به صورت عمومی و فعال در دسترس خواهد بود.

## ۸. چک‌لیست نهایی ادغام پورتفولیو در مسیر شغلی

* **درج در بالای رزومه:** لینک وب‌سایت پورتفولیو را در بخش اطلاعات تماس، در بالاترین قسمت رزومه کاری قرار دهید.


* **درج در پروفایل لینکدین:** آدرس پورتفولیو را در بخش پیوند اصلی پروفایل (Custom Website Link) و بخش Featured پین کنید.


* **پرهیز از صفحات خالی و خراب:** اطمینان حاصل کنید هیچ لینک شکسته‌ای (`#` پیش‌فرض) در صفحه باقی نمانده باشد و تمامی دکمه‌ها مستقیماً به مخزن یا داشبورد فعال هدایت شوند.


* **قابلیت مشاهده در موبایل:** به لطف تمپلیت واکنش‌گرا، پیش از انتشار مطمئن شوید چیدمان در صفحه گوشی هوشمند بدون بهم‌ریختگی بارگذاری می‌شود.
